# Podium: speeches and decks that get a result

Use these rules whenever the user asks for help with a pitch, pitch deck,
presentation, slides, speech, talk, keynote, toast or rehearsal. If
`skills/podium/` exists in this project, follow `skills/podium/SKILL.md` and read
its `references/` instead; this file is the compact version.

## Workflow

1. **Intake.** Use what the user already said. Ask only the missing must-knows
   (goal, audience, setting and length, slides, speaker, material) in one batch,
   each with a suggested default.
2. **Message gate.** Before any structure: the goal as a verb ("after this, who
   does what by when"), a one-line message passing the retell / headline /
   banner / 3-second tests, at most 3 arguments (what the listener gets, with
   proof), and the elephant in the room (what stops them hearing you). Propose
   2–3 candidate messages and wait for the user to confirm.
3. **Structure.** Offer 2–3 that fit, with the outline and time split: proof
   (tell → justify → summarize → invite), situation → problem → solution,
   problem → solution → benefit, Monroe (attention → problem → solution →
   visualize → action), story (situation → action → change); answer-first for
   leaders; problem → why now → traction → team → ask for investors; story →
   meaning → toast for occasions.
4. **Produce** `speeches/<slug>/`: `brief.md`, `script.md`, `slides.md` (if
   slides), `notes.md` (cue cards), `rehearsal.md`. No file access: one chat
   document with the same sections.
5. **Check, then hand over.** Fix what you can; report only what needs the user.

## Script

- Opening, about 15%: curiosity in the first sentence (connect, engage or
  surprise); at most 2 questions; no "hello, my name is…"; write 3 alternatives;
  memorize the first 3–5 sentences.
- Body: claim → proof → what it means for the listener. Short, spoken, active,
  first person. At least one image, one emotion, one rhythm device. Mark pauses.
- Closing: the argument tags as a summary → a CTA more concrete than the message
  (who, what, by when) → optionally your "why" → the last line. Never end on
  "thank you". Protect the closing's time. Add a final close for after Q&A.
- Clarity filters: talk to one non-expert neighbour; active verbs; simple
  words; cut it in half, then in half again.
- Timing: 130 words per minute; plan for at most 90% of the slot.

## Slides

For the listener, not the speaker; skip them if the talk works without.
One idea per slide, a full-sentence assertion headline, a visual as evidence,
at most ~6 other words, no script on the slide. Spec per slide: headline,
visual type and brief, on-slide text, speaker line, and (for decks sent ahead)
a 1–2 sentence leave-behind line. Use a connected slide tool if there is one;
otherwise write a Marp file (`slides.marp.md`) and explain how to render it.

## Rehearsal kit

Timing table; practice plan (3× aloud in your own words, 3-second pause drill,
record and check 120–140 wpm, rehearse in portions, the outsider test); the 3
techniques that fit this speaker best; 8–10 likely questions including the
elephant, with answers of 30 seconds or less that bridge back to the message;
a day-of checklist.

## Hard rules

- Never invent facts, numbers, quotes or names. Write `[NEEDS SOURCE: …]` and list them.
- Message before structure, structure before prose. At most 3 arguments.
- Sell the island (what the listener gets), not the plane (how you work).
- Write in the user's language, in the speaker's own voice.
